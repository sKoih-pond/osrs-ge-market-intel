# ADR-0012: Dashboard served by a Cloudflare Worker at kohstack.tech/ge/

- **Status:** Accepted; spike S2 passed on 2026-10-20 (`docs/spikes/S2_results.md`); amended by ADR-0015

> **Confirmed by S2 (2026-10-20):** an assets-only Worker serves a kohstack.tech path without touching other pages, and the zone's 30-day cache rule does not pin its responses (new content was live 1 s after a redeploy), so no cache-rule change is needed. Decisions from the spike: `not_found_handling: "404-page"` with query-string item pages (the single-page-app fallback turns missing data files into 200 HTML); four routes, exact and wildcard on both `kohstack.tech` and `www`; `_headers` must allow `https://static.cloudflareinsights.com` in `script-src`. Hourly data redeploys upload only changed files (about 16 s). View Transitions are carried to M6 for real-device checks; preview links need a `workers.dev` subdomain (M1 decision).

> **Amended by ADR-0015 (2026-10-20):** published data is shipped inside the Worker's static assets and redeployed by the pipeline. It is never read from R2: no R2 custom domain and no Worker R2 binding on a public route, because those make visitor traffic billable. Fallback if hourly redeploys prove unsuitable: publish data files to the VentraIP host as `/sgn/` does.
- **Date:** 2026-10-20
- **Decided by:** Sylvester (kickoff decision 9)

> **Implemented in M1 (ADR-0016, 2026-10-20):** `site/wrangler.jsonc` is the S2 production config; the M1 page is plain HTML, CSS and JavaScript (Vite arrives in M6). Deploys run only when the repository variable `GE_DEPLOY_ENABLED` is `true`, and a publish counts as `success` only once deployed. Preview links remain an open decision: since 20 October the account has the `kohstack.workers.dev` subdomain (created for ge-clock's Cron Triggers, ADR-0017), but `ge-dashboard` keeps `workers_dev` and preview URLs off.

## Context

The portfolio at kohstack.tech is a React and Vite site on VentraIP behind Cloudflare. It morphs same-tab into `/sgn/` with cross-document View Transitions, which browsers allow only between pages on the same site. The zone caches the whole site at the edge for 30 days and the portfolio deploy clears that cache; `/sgn/*.json` bypasses it. The GE dashboard is a static site whose data changes hourly.

Facts checked on 2026-10-20 (Cloudflare docs):
- Requests to Workers static assets are free and unlimited; only Worker script invocations count toward the free plan's 100,000 requests a day.
- When a route exceeds the limit, its fail mode decides: fail open bypasses the Worker, fail closed returns error 1027.
- For a route such as `example.com/blog/*`, assets must sit in a directory structure that mirrors the path.
- A `_headers` file in the asset directory sets response headers (up to 100 rules); it does not apply to responses generated by Worker code.

## Decision

- The dashboard is built with Vite (base path `/ge/`) and deployed as a Worker with static assets, routed at `kohstack.tech/ge/*` (and `www.kohstack.tech/ge/*` or a redirect, settled by S2).
- Assets only, with no per-request script, in v1. Single-page-app fallback through `not_found_handling`, settled by S2.
- Security headers in `_headers`, matching the portfolio's posture (CSP with `connect-src` limited to the data origin, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`).
- `/ge/*` is excluded from the zone's 30-day edge-cache rule. Hashed assets are long-lived; HTML and data revalidate.
- Published data (`ge-intel-public/v1`) is read either through an R2 custom domain or a Worker R2 binding; S2 compares the two.
- Deploys run from the GE repo's CI with a Cloudflare API token limited to Workers scripts and routes on the kohstack.tech zone, created by Sylvester. Rollback is a one-command return to the previous version.
- The portfolio tile and the same-tab morph are added in M6 through the website workflow.

## Consequences

- GE releases are independent of the portfolio's FTP deploy, yet the dashboard lives on the same site.
- If the Worker breaks, only `/ge/` is affected; the route pattern is tested so it cannot catch other paths.
- One more Cloudflare object to manage, recorded in the repo as configuration.

## Alternatives considered

- `ge.kohstack.tech` on Cloudflare Pages: simpler, but no same-tab morph.
- `kohstack.tech/ge/` deployed through the portfolio repo over FTP: ties GE releases to portfolio CI.
- Pages plus a forwarding Worker: one more moving part, and every page request runs script code.
